# Universal Methodology

Use this skill when a request needs judgment before execution. The goal is not to make every matter heavier. The goal is to prevent default assumptions, social pressure, urgency, or vague goals from driving the work.

## When To Use

Use for:

- ambiguous tasks where the right target is not obvious;
- high-stakes decisions where reversal cost is meaningful;
- reusable work that may become a SOP, asset, or future skill;
- project scoping, decision review, execution planning, QA, or closeout;
- source notes that may need to be harvested into a method, not merely summarized.

Avoid for trivial one-step actions, pure emotional expression, or experiences that should remain unstructured.

## Core Flow

```text
Capture -> Default Check -> Target Calibration -> Orient -> Define
-> Position And Resources -> Architect -> Orchestrate -> Execute
-> Decision QA And Deliver -> Close And Harvest
```

Use the smallest useful subset.

## Matter Types

- Build: creates an output or compounding capability.
- Maintain: preserves stability or repairs a system.
- Explore: gathers information before committing.
- Experience: value is in the experience itself.
- Relationship: trust and emotion matter more than speed.
- Recovery: restores energy, health, or subjectivity.
- Method harvest: turns source material into reusable practice.

## Guardrails

- Check whether the target is worth wanting before optimizing execution.
- Do not turn every note into a rule or asset.
- Prefer downgrade, delay, or close when the value is unclear.
- Add safeguards when the failure cost is high.
- Harvest only when reuse value exceeds extraction cost.
