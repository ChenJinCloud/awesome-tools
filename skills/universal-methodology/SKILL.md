# Universal Methodology

Use this skill to move a matter from vague input to a judged, bounded, executable, and closable structure without over-managing everything.

The v1.2 emphasis is decision quality before progression: do not merely help the user execute a matter faster. First check whether the target is right, whether default values are driving it, and whether progressing it improves the user's future position.

## Operating Principle

Start by deciding whether the matter deserves structure at all. Do not assume every input should become a task, deliverable, or reusable asset.

Keep the result "80-point useful": enough structure to reduce ambiguity and rework, not enough structure to create friction.

Prefer the smallest useful mode:

- Quick Diagnosis: classify the matter and give the next state transition.
- Decision Review: test default values, target correctness, position impact, options, and safeguards.
- Execution Plan: scope the next concrete deliverable and rhythm.
- Full Planning: use the full progression card when the matter is large or handoff-heavy.
- Close & Harvest: decide whether to close, archive, extract methodology, create a SOP/skill, or do nothing.
- System Methodology Extraction: when the user provides notes, excerpts, retrospectives, or examples, extract system principles and placement decisions before suggesting behavior changes.

## Core Flow

Use this sequence:

```text
Capture -> Default Check -> Target Calibration -> Orient -> Define -> Position & Resources -> Architect -> Orchestrate -> Execute -> Decision QA & Deliver -> Close & Harvest
```

Chinese labels:

```text
事项收拢 -> 默认值诊断 -> 目标校准 -> 事项定性 -> 边界定义 -> 位置与资源判断 -> 结构设计 -> 协同编排 -> 节律执行 -> 决策质控与交付 -> 收束采收
```

## How To Respond

1. Capture the matter: name, source, why now, deadline, recipient, existing materials, current pressure.
2. Choose the smallest useful output mode. Do not use the full card unless the matter warrants it or the user asks.
3. Diagnose default-value drift: emotion, ego, social pressure, inertia, or body/energy state.
4. Calibrate the target: what result is being pursued, whether it is worth wanting, who/what set the target, and what would count as the right result.
5. Orient before planning: classify the matter and decide whether to progress, delay, downgrade, abandon, simply experience it, or harvest it.
6. Define boundaries: target, current state, constraints, minimum deliverable version, success criteria, and what not to do.
7. Check position and resources: whether the matter improves future options, buffers, trust, capability, information quality, and whether time, energy, money, rest, opportunity cost, or irreversible resources are justified.
8. Architect the work: lifecycle stage, state chain, modules, interfaces, rework-prone parts, resource chain, risk chain, and safeguards.
9. Orchestrate responsibilities: AI, tools, user, other people, and environment/system.
10. Execute by rhythm: one state transition per round where possible; include duration, interruption point, recovery method, buffer, and downgrade path.
11. QA both decision and output: goal correctness, default-value risk, options considered, safety margin, process record, deliverable quality, system cost, and downstream impact.
12. Close deliberately: choose close, archive, or harvest. Harvest only when reuse value exceeds extraction cost.

## Matter Types

Use these categories during Orient:

- 建设型事项: needs output, accumulation, compounding, or delivery.
- 维持型事项: preserves stability, repairs systems, or prevents collapse.
- 探索型事项: gathers information or opens possibilities without rushing to conclusion.
- 体验型事项: value is in the experience itself; may not need assets.
- 关系型事项: prioritizes trust, emotion, and collaboration over efficiency.
- 恢复型事项: restores energy, body, emotion, or subjectivity.
- 方法论采收型事项: turns notes, excerpts, retrospectives, or examples into system principles, methodology docs, SOPs, skills, assets, or explicit no-action decisions.

## Guardrails

- Do not optimize execution until target correctness has been checked.
- Do not treat every source note as a behavior change. First decide whether it belongs in reading digestion, methodology, asset, skill/SOP, project execution, or no action.
- Prefer downgrade, delay, or close when the target is unclear or the resource budget is not justified.
- Do not optimize relationship, recovery, or experience matters as if they were production tasks.
- Do not assetize by default. Harvest only if the pattern is likely to repeat and extraction cost is lower than future savings.
- If the user asks for execution, turn the current phase into the next concrete state transition, not a complete life plan.
- If pressure is high, include a rest, body-state, and buffer check before expanding scope.
- If failure cost is high, include safeguards: safety margin, delay before public commitment, reversible test, tripwire, or exit condition.
