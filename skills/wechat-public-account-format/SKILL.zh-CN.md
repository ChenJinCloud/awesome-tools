# 公众号排版（chenjin.io）

[English](SKILL.md) | [简体中文](SKILL.zh-CN.md)

将本地 Markdown 原稿转换为可以直接复制到微信公众号后台的 HTML 成品。适用于公众号文章、个人复盘、OKR、教程、知识卡片和带表格的长文。

## 默认输出

- 不修改、不覆盖原始 Markdown。
- 默认在原稿同目录生成“原文件名-公众号版.html”。
- HTML 只使用内联样式，不依赖外部 CSS、JavaScript 或在线字体。
- 用户明确要求“同步到草稿箱”时，才进一步讨论公众号 API；默认只生成可复制版本，不自动发布。

## 视觉与字号规范

默认使用 chenjin.io 风格的配色：

- 月白/浅青背景：#EFF8F4
- 青黛标题与正文：#223939
- 翠涛主强调色：#2F8E7D
- 深翠涛文字：#2F7E6F
- 月白淡区块：#E6F1EB
- 薄荷淡区块：#EEF6F1
- 松花淡边框：#D0E1D8
- 胭脂辅助色：#B35F6B
- 暖棕辅助色：#A8754A

默认字号：

- 正文、段落、列表：14px
- 主标题：26px
- 一级标题：20px
- 二级标题：17px
- 表格文字：12px
- 表格中的分类标签：13px

关键兼容规则：

- 正文字号必须写在每个 p、li 元素上，不依赖外层继承。
- 表格字号必须写在每个 th、td 元素上。
- 常见 SWOT 分类标签使用翠涛、胭脂、松绿和暖棕辅助色，保持信息层级但不喧宾夺主。
- 以“**核心动作：**”开头的段落转换为单格表格色块，并把背景色、文字色、字号都写到单元格和文字节点上。
- 表格使用内联边框和背景色；复杂嵌套布局应改为可读的表格或普通区块。

转载或翻译 Blog 时，页首按“主标题 → 封面图 → 两行右对齐的浅色信息”排版。两行依次为“发布日期 · 阅读时长 · 分类”和“原作者 · 经核实的公司及职务”；从原文读取，不写死作者身份。渲染脚本会识别 Markdown 开头的“标题 → 信息 → 作者 → 封面”或“标题 → 封面 → 信息 → 作者”，统一输出上述版式。日期行需以中文年份（如 `2026 年`）开头，作者行需以 `原作者：` 开头。

## Blog 翻译与转载流程

用户要求翻译或转载 Blog 时，先保存原文和来源信息，再制作单独的中文 Markdown；不要覆盖原文，也不要把排版脚本当作翻译器。

1. **核对原文。**记录原文 URL、标题、发布日期、原作者、可核实的机构与职务、栏目或分类。阅读时长可按正文估算，标明“约”；原文缺失的字段不编造。对照原网页检查段落、数字、术语、引语、链接和参考资料，逐处解决抓取或转换产生的占位符，不让 `__WPA_HOLD_...` 等内部标记出现在成品中。
2. **收齐图片。**盘点封面和正文内全部配图，按原文顺序下载实际文件，保留图片与原 URL 的对应关系、说明或替代文字。核实下载结果是可用图片，不能把候选 URL 当成已下载素材；译稿中的图片路径应指向本地文件。图注和位置随原文保留。
3. **做忠实译稿。**保留论证结构、数据、条件、出处与作者观点。对拿不准的专业表达先核原文，不把推断写成事实。原作者社交链接和论文、代码等资料链接按原文保留；译者补充内容需明确标为编者内容。
4. **用简洁版式。**页首固定为主标题、封面、两行浅色右对齐信息；正文以标题、段落、列表和原图为主，避免大量卡片与装饰。需要“太长不看”底色时，只给这一处使用克制的浅色块，不扩展成整篇卡片排版。
5. **收拢来源。**文末使用紧凑的“原文与参考资料”：英文原文链接在前，参考资料按顺序编号；每条第一行写作者、来源、年份等信息，第二行用较小、浅色文字写完整原文标题，条目间用细分隔线。不要给每条资料重复使用醒目的绿色下划线。论文、代码等附加链接保留可访问地址；公众号清洗正文链接时，另在后台设置原文链接并核对预览。Markdown 中使用 `## 参考资料` 的列表，随后用 `## 原文链接` 加单独一条 Markdown 链接，脚本会在识别为 Blog 稿时自动生成此版式。
6. **按授权交付。**先检查本地 HTML 中的封面、配图、署名、参考资料和占位符。用户要求同步草稿时，再上传所有图片、设置封面与原文链接，核对公众号后台预览和草稿状态。正式发布仍以用户对发布的授权为准。文末栏目介绍、个人微信和行动引导只在该篇明确需要时加入，不能把某篇文章的作者、品牌或联系方式设为通用默认值。

## 执行方式

优先使用配套脚本：

~~~bash
python3 skills/wechat-public-account-format/scripts/render_wechat.py \
  "/path/to/article.md"
~~~

可选参数：

~~~bash
python3 skills/wechat-public-account-format/scripts/render_wechat.py \
  "/path/to/article.md" \
  --output "/path/to/article-公众号版.html" \
  --title "文章标题"
~~~

脚本支持常见 Markdown 标题、段落、粗体、斜体、行内代码、链接、图片、无序/有序列表、引用、水平线和 Markdown 表格。

## 处理边界

- 只做结构化排版，不擅自改写原文、补充观点或翻译内容。
- 图片保留原引用并给出兼容性提醒：本地图片路径通常不能随 HTML 一起粘贴进公众号，需要在公众号编辑器中重新上传。
- 外部链接保留为安全链接；不把脚本、外部样式或跟踪代码带入成品。
- 公众号可能清洗粘贴后的 HTML、移除正文外链或改变字号。以后台预览为准；必要时单独设置原文链接，或在编辑器中调整字号。
- 不把“生成 HTML”“保存草稿”“预览”和“正式发布”混为同一状态。
- 未经用户明确授权，不正式发表文章。

## 验收

生成后检查：

1. 输出文件存在，且原始 Markdown 的修改时间和内容未被改变。
2. HTML 没有 link、script、外部 CSS 或外部字体依赖。
3. 正文 p、li 都有明确字号；表格 th、td 都有明确字号。
4. 标题、核心动作色块、表格、引用和附录等主要结构完整。
5. 用浏览器打开输出文件预览，再复制到公众号草稿箱校对。
