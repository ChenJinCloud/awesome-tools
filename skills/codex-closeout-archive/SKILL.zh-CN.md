# Codex 对话收尾归档

[English](SKILL.md) | [简体中文](SKILL.zh-CN.md)

当用户明确要求结束、关闭、归档、采收或保存一段 Codex 对话时，使用此 Skill。它先把对话转换成轻量的过程资产，然后归档对话。

用户明确提出 closeout，就是作出资产化决定。此 Skill 一旦启用，不要重新争论该任务是否值得保存；每次 closeout 都必须创建一份精简的过程资产。

## 为什么需要这个 Skill

Codex 任务经常承载真正的工作过程：意图转变、用户纠正、证据路径、文件修改、外部来源检查和最终决定。如果只在应用中归档任务，下一次对话可能不知道决定为何发生变化。

此 Skill 不复制完整对话，而是保留可复用的轨迹。它保护：

- 可追溯性：未来工作能够找到原会话、文件和证据。
- 决策连续性：关键转折和纠正可以跨任务保留。
- 低摩擦收尾：每次结束只生成一份有用资产，而不是庞大的归档系统。

不要仅仅因为对话安静下来，或 Agent 想整理界面就使用此 Skill。只有当用户要求 closeout、归档、采收或保存时才使用。

## 不可妥协的规则

- 每次使用此 Skill 都必须创建一份过程资产。
- 默认把过程资产写入调用 Skill 时所在的当前工作区或项目文件夹。
- 时间线保持精简，通常保留 5–12 个关键节点。
- 保留关键转折、用户纠正、决定、输出文件和证据路径。
- 不要在资产中粘贴完整原始对话、完整 Slack 或私信内容、凭证或敏感导出。
- 不要删除、移动或改写原始 Codex 会话文件。
- 资产写入并验证后归档当前对话，除非用户只要求准备资产而不结束任务。

## 工作流

### 1. 确定目标位置

目标位置遵循位置契约：把过程资产写入用户调用此 Skill 时所在的当前工作区或项目文件夹。这样 closeout 可以跨项目移植：在项目 A 中使用，就归档到项目 A；在文件夹 B 中使用，就归档到文件夹 B。

按以下顺序选择：

1. 用户在 closeout 请求中明确指定的目标文件夹。
2. 当前任务环境或会话元数据中的工作目录。
3. 只有当当前仓库或工作区根目录就是用户正在操作的同一项目文件夹时，才使用该位置。
4. 本地 `AGENTS.md` 或同等工作区规则要求的持久项目文件夹，但前提是规则明确规定了 closeout 或过程资产的存放位置。

不要在当前工作区之外广泛搜索一个“更相关”的项目文件夹。只有当无法确定当前文件夹，或本地规则与用户指定位置冲突时，才提出一个简短问题。

如果目标文件夹有持久记录系统，写入前遵守最近的 `AGENTS.md` 或同等项目规则，同时确保资产仍位于同一个目标项目内。

文件名示例：

```text
<topic-slug>__codex-process-asset__YYYY-MM-DD.md
```

如果没有明显的主题名称，使用：

```text
codex-closeout__YYYY-MM-DD.md
```

### 2. 定位证据

写入资产前记录证据路径。

查找：

- 当前工作区路径。
- 当前或已归档的 Codex 会话 JSONL 路径。
- JSONL `session_meta` 中的线程 ID（如果存在）。
- 对话中创建、修改、移动或验证的文件。
- 读取或写入的外部系统；在适合保留的情况下记录链接或查询名称。

会话文件通常位于：

```text
~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl
~/.codex/archived_sessions/rollout-*.jsonl
```

在 Windows 中，`~` 通常解析为用户配置文件目录。

如果关闭任务时仍未在磁盘上找到当前实时会话，明确写入：

```text
Codex 会话证据：当前实时任务；closeout 时未找到 JSONL。
```

可选辅助程序：

```bash
python scripts/extract_session_events.py --latest
python scripts/extract_session_events.py --session "/path/to/rollout.jsonl"
```

辅助程序只用于获得原始事件清单。最终时间线必须由你自行筛选。

### 3. 编写过程资产

使用以下结构：

```markdown
# <标题> Codex 过程资产

归档日期：YYYY-MM-DD
归档时间：YYYY-MM-DD HH:mm+TZ
工作区：`<绝对路径>`
本地项目：`<绝对路径>`
Codex 会话证据：`<绝对路径或实时任务说明>`
线程 ID：`<id 或 unknown>`

## 1. 资产类型

此文件是一份过程资产。它保存 Codex 对话的关键演变，而不是完整原始对话。

## 2. 为什么保存

- <为什么这次收尾值得保存>
- <未来读者应当从此资产中恢复什么>

## 3. 精简时间线

| 时间 | 事件 | 含义 |
| --- | --- | --- |
| <时间> | <关键转折> | <为什么重要> |

## 4. 输出与证据

| 类型 | 路径 / 链接 | 说明 |
| --- | --- | --- |

## 5. 决定与纠正

- <最终决定>
- <重要用户纠正>
- <已明确的边界>

## 6. 未完成事项

- <事项或“无”>

## 7. 边界

- 未复制原始私有消息、凭证或完整 Codex JSONL 内容。
- 原始会话文件保持原位。

## 8. 检索标签

- <标签>
```

保持文字精简。资产应当能够在一两分钟内读完并重新理解。

### 4. 更新附近索引

如果存在，更新最小的附近发现入口：

- 项目文件夹中的 `README.md` 或 `index.md`，前提是其中包含资产表或来源映射。
- 项目文件夹中的 `CHANGELOG.md`（如果存在）。
- `AGENTS.md` 或同等工作区政策要求的本地运行台账或项目索引。

除非没有合理的项目文件夹，否则不要专门为 closeout 创建新文件夹。

### 5. 验证

完成前确认：

- 过程资产存在于目标路径。
- 资产包含会话证据路径或实时任务说明。
- 所有需要更新的索引或变更日志都提到了新资产。
- 已列出修改的文件。

### 6. 最终回复并归档

简要回复：

- 过程资产路径。
- 更新过的索引或变更日志文件。
- 证据路径状态。
- 仍未完成的后续事项。

然后归档当前对话。在 Codex Desktop 中，将归档指令作为最后一行输出：

```text
::archive{reason="Closeout process asset created and conversation archived"}
```

只有当用户要求准备 closeout 但不结束任务时，才跳过归档指令。

## 示例

下列请求应使用此 Skill：

- “结束这个 Codex 任务并创建一份可追溯的过程资产。”
- “归档这段对话，保留关键决定和证据路径。”
- “用一份精简过程资产结束这个任务。”
- “执行 closeout，把输出路径和会话证据留在项目文件夹中。”
